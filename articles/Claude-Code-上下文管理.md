# 🧠 Claude Code 上下文管理

> 一句话核心：**上下文不是被动容器，而是最昂贵的战略资源，需要主动调度与防守。**

---

## 🧅 四层防御系统（洋葱结构）

### 第一层：微压缩（Zero-Cost 规则层）

- **方式**：纯规则清理，不调用大模型，成本 ≈ 0
- **目标**：清理低价值、短时效的工具输出（如读文件、grep、网页抓取）
- **核心机制**：
  - 只保留最近几轮工具结果
  - 精细保护 Anthropic API 的**前缀缓存**

#### 🔧 双轨决策机制（防缓存失效）

| 场景 | 策略 | 做法 |
|------|------|------|
| 用户高频聊天，缓存仍有效 | `cache_micro_compact` | 发“纸条”从缓存中删除旧工具结果，不动前缀 |
| 用户离开久，缓存已过期 | `homebase_micro_compact` | 本地替换长工具输出为简短占位符 |

#### ⚠️ 工程细节：主线程隔离

- 主线程（聊天）与子线程（后台记忆提取）**使用不同账本**
- 避免删错数据 → 严格限定压缩只对主线程生效

> 💡 启示：删除内容之前，先确认会不会破坏缓存或跨线程状态。

---

### 第二层：会话记忆压缩（结构化提炼）

> 不是做“摘要”，而是做“结构化事实”

- **做法**：派一个绿色 `fork_agent` 提炼出：
  - 项目技术栈
  - 迁移进度
  - 编码风格等
- **存储**：固化到 `memory.md`

#### 📏 控制盘（保留策略）

| 维度 | 下限 | 上限 |
|------|------|------|
| Token 数 | 1万 | 4万 |
| 消息条数 | 5条 | 无硬上限 |

#### 🔗 结构边界锁（极易踩坑）

- 截取时**必须成对保留**：
  - `tool_result` ←→ 对应的 `tool_call`
  - 同一个 `message_id` 下的 thinking + tool_use
- 否则 API 报 400 错误

> 💡 启示：上下文截断不是按字数切，而是按 API 语义结构切。

---

### 第三层：完整压缩（重型武器，真金白银）

- **触发条件**：前两层不够用
- **方式**：调用大模型，从 9 个维度复盘（意图、修复等）

#### ✨ 核心设计妙招：草稿纸模式

```text
[analysis]  ← 模型强制写推理过程（会被丢弃）
[summary]   ← 最终摘要（保留）
```

- 模型必须先思考，再输出
- 系统**丢弃草稿**，只保留摘要
- 本质是 **Chain-of-Thought 的工程化落地**

> 💡 启示：让模型思考，但别让思考内容占用正式上下文。

#### 🚨 过载保护

- 压缩请求本身可能超长 → 触发 `tool_error`
- 解决方案：
  - 按 API 轮次分组
  - 从最老旧记录开始丢弃
  - 最多重试 3 次

#### 🔧 战后重建（极其关键）

压缩后必须立刻：

1. 清空当前缓存
2. 重新注入：
   - 最多 5 个关键文件（5万 token）
   - 项目 plan
   - skill 内容
   - MCP 工具说明

> 否则模型会“失忆”，不知道该调什么工具、看哪行代码。

> 💡 启示：压缩不是“删完了事”，而是“破而后立”。

---

### 第四层：自动触发（扣扳机 + 熔断器）

#### ✅ 触发条件（每次模型调用后检查）

```text
当前 token > 窗口上限 - 13000（安全缓冲）
```

- 优先走第二层（结构化压缩）
- 不够再走第三层（大模型压缩）

#### 🔥 熔断器（真实血泪教训）

- **2026年3月事故**：某个会话压缩失败 3272 次
- 全局每天浪费 25 万次 API 调用
- **解决方案**（仅三行代码）：
  - 连续失败 ≥ 3 次 → 强制停止重试
  - 类似电路跳闸

#### 🔁 死锁防御

- 明确排除 `session memory` 和 `compact` 这两个子 agent
- 防止“为压缩做压缩”的无限套娃

> 💡 启示：系统设计必须考虑失败路径和自引用循环。

---

## 🧱 源头管控：不让上下文“胖”起来

### 数据体积控制：指针替换

- 大块数据（如脚本输出） → 存外部存储
- 上下文中只放：
  - 短指针
  - 一句摘要
- 模型想看细节 → 按需取

### 工具数量控制：按需加载

- 80+ 工具，初始只加载最核心的几个（如读写文件）
- 其他通过 MCP 远程发现
- 配合 `schema` 严格校验格式

> 💡 目的：防止模型“选择困难症” → 错误 → 重试 → 上下文污染。

---

## 📊 四层机制总结表

| 层级 | 名称 | 成本 | 核心动作 | 典型产出 |
|------|------|------|----------|----------|
| 1 | 微压缩 | 零 | 规则清理 + 缓存保护 | 删旧工具结果 |
| 2 | 会话记忆压缩 | 低 | 结构化提炼 | `memory.md` |
| 3 | 完整压缩 | 高 | 大模型复盘 + 草稿丢弃 | 最终摘要 |
| 4 | 自动触发 | 系统级 | 熔断 + 死锁防御 | 停止无限重试 |

---

## 🧠 最终心法（工程哲学）

> ❌ 错误认知：上下文是一个静态容器，没装满就塞。  
> ✅ 正确认知：上下文是最稀缺的战略资源，必须**主动调度、带攻击性地防守**。

### 三条黄金原则：

1. **永远不要问“还能装多少”**  
   → 而要问“这条数据该不该装”
2. **保护缓存 > 节省 token**
3. **压缩不是结束，战后重建才是**
