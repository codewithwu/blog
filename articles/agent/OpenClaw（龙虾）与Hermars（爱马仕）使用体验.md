# OpenClaw（龙虾）与 Hermars（爱马仕）对比学习笔记

## 一、记忆机制

| | OpenClaw | Hermars |
|---|---|---|
| 逻辑 | 错题集：记录错误，下次检索 | 内化：合并相似经验，丢弃不重要的 |
| 记忆文件大小 | 会越来越长 | 固定约 2000 字符 |
| 检索方式 | 向量搜索，消耗大量 token | 不依赖长文本 |
| 体感 | 错题集太长时命中率下降 | 批评后能真正用起来 |

## 二、多智能体稳定性

| | OpenClaw | Hermars |
|---|---|---|
| 架构 | 所有 agent 共享一个 gateway | 每个 agent 独享一个 gateway |
| 故障影响 | 一个 agent 改错配置 → 全部挂起 | 故障 agent 不影响其他 |
| 恢复 | 需人工或外部 agent 修复 | 自动隔离 |
| 权限与审计 | 难以区分 | 可进程级控制、独立追踪 |

## 三、主动性与技能沉淀

| | OpenClaw | Hermars |
|---|---|---|
| 技能来源 | 用户手动写/提炼 | agent 自动沉淀 |
| 机制 | 无 | 统计工具调用次数 >10 → 独立 agent 审计 → 创建或更新 skill |
| 体感 | 员工不会写 skill 是卡点 | 越用越好用，工作流自动成熟 |

## 四、交互细节

| | OpenClaw | Hermars |
|---|---|---|
| 消息处理 | 必须处理完当前消息才能响应下一条 | 新消息可随时打断、纠正任务 |
| 错误纠正 | 无法中途纠正，需关掉会话重开 | 随时发消息即可纠正方向 |
| 体感 | 死板、机器感强 | 符合直觉，灵活 |
